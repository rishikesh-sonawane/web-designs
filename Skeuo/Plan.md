## ROLE

Act simultaneously as:

* Senior Product Designer

* UX/UI Director
* Senior Frontend Engineer
* Interaction Designer
* Motion Designer
* Design Systems Specialist
* Visual Design Specialist
* Web Performance Engineer
* Accessibility Specialist
* Conversion-Focused Web Designer

You are working on an existing **Skeuomorphic web design prototype**.

Your job is NOT simply to make the current website prettier.

Your job is to transform the existing project into an **exceptionally polished, portfolio-grade, commercially believable, premium digital experience** that demonstrates mastery of modern skeuomorphic design.

The final result should feel like something created by a highly skilled independent digital studio for a premium real-world brand.

It must NOT feel like:

* a generic website template
* an old Apple iOS clone
* a 2010-era web design
* a Dribbble concept that was never made usable
* a design-system experiment

* an excessive texture showcase

The goal is:

> **Modern digital product design with physical character.**

The user should feel that they can almost **touch, press, drag, open, slide, flip and manipulate the interface**.

But underneath that physicality must be an extremely clean, intuitive, fast and accessible digital experience.

# 1. FIRST — AUDIT THE EXISTING PROJECT

Before changing anything:

1. Inspect the entire project.

3. Identify the strongest existing visual ideas.
4. Identify reusable components.
5. Identify existing textures, illustrations, icons and assets.

The final result should clearly retain the strongest character of the original Skeuo concept while becoming dramatically more sophisticated.

# 2. CORE DESIGN OBJECTIVE

Build a **modern premium skeuomorphic experience**.

The central design philosophy is:

> Digital interface + physical metaphor + tactile interaction + modern usability.

Skeuomorphism should not mean:

> "Make everything look realistic."

It should mean:

> "Use physical characteristics when they make the interface more understandable, memorable, tactile or emotionally compelling."

Every physical metaphor must have a reason to exist.

Before adding any object, texture, shadow, bevel, reflection, stitch, knob, switch, paper edge or material effect, ask:

**Why does this exist?**

If the answer is only:

> "Because it looks cool."

remove it.

If the answer is:

> "Because it reinforces the brand, interaction or physical metaphor."

keep it.

# 7. PHYSICAL LIGHTING SYSTEM

This is one of the most important parts of the project.

Do not use random shadows.

Create a consistent imaginary light source.

Define:

* light direction
* softness
* intensity
* contact shadow
* ambient shadow
* highlight direction

Every physical object should obey the same lighting logic.

For example:

If light comes from the upper-left:

* upper-left edges receive subtle highlights
* lower-right edges receive shadow
* objects create believable contact shadows
* raised elements cast shadows consistently

This consistency is what separates premium skeuomorphism from cheap visual effects.

---

# 8. SHADOW SYSTEM

Create a centralized shadow system.

Use different shadows for:

### Resting object

Very subtle contact shadow.

### Raised object

Slightly larger, softer shadow.

### Pressed object

Reduced elevation and stronger contact.

### Floating object

Soft, larger ambient shadow.

### Modal

Strongest elevation but still restrained.

Never use gigantic generic `box-shadow` values.

Shadows should communicate:

> physical position.

Not:

> decoration.

# 10. TACTILE INTERACTION IS THE HEART OF THIS PROJECT

The website should feel physically responsive.

When users interact with something:

### Hover

Object may:

* lift 2–4px
* brighten slightly
* reveal a subtle highlight
* deepen or soften shadow
* move slightly toward cursor

### Press

Object may:

* move downward 1–3px
* reduce elevation
* compress visually
* strengthen contact shadow

### Release

Object should:

* return naturally
* use a subtle spring
* settle quickly

Avoid cartoonish bouncing.

The user should think:

> "That feels physical."

Not:

> "That button has an animation."

* mobile
* low-power devices
* reduced-motion settings

---

# 40. ANIMATION PERFORMANCE

Prefer:

* `transform`
* `opacity`

Avoid continuously animating:

* `top`
* `left`
* `width`
* `height`
* layout-heavy properties

Use `will-change` sparingly.

Do not place:

```css
will-change: transform;
```

on hundreds of elements.

Use it only when there is a real performance reason.

For custom animation loops:

use `requestAnimationFrame()` appropriately.

Avoid unnecessary scroll event calculations.

Use efficient viewport detection for reveal animations.

---

# 41. REDUCED MOTION

```css
@media (prefers-reduced-motion: reduce)
```

For reduced-motion users:

* remove parallax
* reduce object movement
* remove unnecessary spring
* remove large transitions
* preserve essential state changes
* keep interaction understandable

Do not disable important functionality.

* performant
* understandable

* richer interaction
* larger objects
* subtle cursor behavior

Tablet:

Mobile:

* simplified physical scene
* touch-first interaction
* reduced texture complexity
* reduced animation
* stronger content hierarchy

The design language must remain intact.

# 55. IMAGE AND ASSET OPTIMIZATION

For all assets:

* use appropriate dimensions
* compress images
* use WebP/AVIF where appropriate
* use SVG for vector graphics
* use responsive image sources
* lazy-load non-critical assets
* preload only genuinely critical assets
* avoid enormous source images

Do not load a 5000px image to display it at 500px.
