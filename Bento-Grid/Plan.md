# 2. CORE DESIGN PHILOSOPHY

The Bento Grid should NOT be treated as:

> "Cards of different sizes."

It should be treated as:

> **A spatial system for organizing different types of information according to importance.**

Every module must have a reason for:

* its size
* its position
* its visual weight
* its content
* its interaction
* its relationship with neighboring modules

Before creating a tile, ask:

**Why is this module this size?**

A large module should communicate:

> high importance.

A small module should communicate:

> supporting information.

A wide module should communicate:

> narrative or horizontal information.

A tall module should communicate:

> depth, imagery, or vertical content.

A featured module should clearly dominate.

Create sequences such as:

**Large → Small → Medium → Large**

**Image → Text → Interaction → Image**

**Dense → Quiet → Dense → Spacious**

> Card → Card → Card → Card → Card → Card.

* large whitespace
* full-width moments
* oversized typography
* immersive images
* interactive modules
* edge-to-edge sections

# 12. NEGATIVE SPACE

* empty areas

# 13. ASYMMETRY

# 14. FULL-BLEED MOMENTS

Not everything has to remain inside cards.

Occasionally allow a module to:

* span the entire container
* touch the viewport edge
* break the grid
* become a full-width image
* become an immersive visual

This prevents the entire website from becoming:

> rounded card soup.

Use this sparingly.

# 15. BREAK THE GRID — BUT WITH PURPOSE

A sophisticated Bento design can occasionally escape its own grid.

Examples:

* image breaks outside module
* oversized number overlaps two tiles
* product extends beyond card boundary
* typography crosses grid lines
* visual object sits between modules

However:

The underlying grid must still be perceptible.

Controlled rule-breaking creates originality.

# 23. TILE EXPANSION — IF USED

If a tile expands:

The transition must preserve spatial continuity.

Do NOT simply:

> fade card out → open modal.

Instead:

1. selected tile begins expanding
2. surrounding content responds
3. tile grows toward its destination
4. content scales/reflows
5. expanded view appears
6. close returns to the original spatial position

The user should understand:

> "This is the same object becoming larger."

not:

> "A random modal appeared."

---

Possible:

* 1–3px lift

* image zoom 1–2%
* border emphasis
* icon movement
* content reveal
* subtle gradient movement
* internal element translation

Avoid:

* 10% scaling
* card rotation
* excessive shadows
* neon glow everywhere
* giant cursor effects

# 25. TOUCH INTERACTION

On touch:

# 26. TILE PRESS FEEDBACK

# 27. SCROLL REVEALS

Use scroll-driven animation selectively.

Good:

* tiles fade in
* tiles translate 8–24px
* large module reveals
* image masks open
* typography reveals
* related modules stagger

Bad:

* every card flying from a different direction
* huge rotations
* slow animations
* scroll-jacking

Use a coherent motion system.

---

# 28. STAGGER SYSTEM

For a row of modules:

1. first module
2. second module
3. third module

Use subtle stagger.

For example:

* 40–100ms offsets

depending on density.

Do not use huge 300–500ms delays that make the page feel slow.

---

# 29. SCROLL-DRIVEN STORYTELLING

Use sticky sections where they genuinely improve understanding.

Example:

Left side:

> Feature explanation.

> Bento product modules change as the user scrolls.

Do not use sticky sections simply because they look impressive.

---

# 30. PARALLAX

Use very subtle parallax inside large image modules.

For example:

Background image:

slower than content.

Foreground product:

slightly faster.

Keep movement restrained.

Disable/reduce it where:

* mobile performance suffers
* reduced motion is requested
* it harms readability

---

# 31. IMAGE REVEALS

* shadows
* mobile wrapping

---

# 77. MOTION CHOREOGRAPHY

Create a hierarchy of motion.

### Level 1 — System

Page transitions / section reveals.

### Level 2 — Module

Tile interaction.

### Level 3 — Element

Icon/text/image movement.

### Level 4 — Feedback

Button press / hover / loading.

Do not animate all four levels simultaneously.

That creates noise.

---

# 78. MOTION SHOULD FOLLOW ATTENTION

When something important appears:

motion may guide attention.

When something is secondary:

motion should be weaker.

Motion is part of the information hierarchy.

# 79. LOADING STATES FOR INTERACTIVE MODULES

* idle
* interaction
* processing
* success
* failure

Do not make the user wonder whether their action worked.

# 80. MOBILE MOTION

* fewer simultaneous animations
* less parallax
* simpler hover equivalents

Touch interactions should respond immediately.

Do not make mobile wait for cinematic sequences.
